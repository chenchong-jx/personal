# AI 智能付款高保真原型

依据《AI智能付款PRD V1.0》评审稿（2026-10-14），使用 Vue 3、Ant Design Vue 4、Vite 实现。界面为面向企业经办人的桌面财务工作台，并适配小屏。

## 本地运行

```bash
cd /workspace/personal
npm ci
npm run dev
```

默认端口 5173。生产构建使用 `npm run build`，预览构建使用 `npm run preview`。不需要环境变量或外部服务。

## 页面与主流程

- 入口：真实发票、虚拟发票双路径选择；助手解释下一步，结构化卡片负责关键操作。
- 合同弹窗：名称、编号筛选；单选、分页、重置、取消、确定；选择后回显合同主数据与类型。
- 真实发票：业务类型与必填摘要 → 合同 → 机场服务月 → 批量附件 → 主动解析 → 逐票核对 → 核对确认 → 整批验证 → 财务供应商确认 → 录入完成 → 创建确认 → 起草回填预览。
- 虚拟发票：合同 → 多条明细新增、编辑、删除 → 机场合同逐条服务月区间 → 分币种汇总 → 录入完成 → 创建确认 → 起草回填预览。
- 右侧概览：随路径、合同、明细变化同步更新，不将不同币种相加。
- 起草预览：回显合同、业务摘要、服务月、供应商及各条票据，明确尚未审批或付款。

## 推荐评审路线

1. 真实路径填写业务摘要，选择一份履行中的合同。
2. 添加两张示例发票，点击解析，在“核对”抽屉查看并编辑全部 12 项字段。
3. 勾选核对确认，切换“演示：失败与回滚”，查看整批失败和全部占用回滚提示。
4. 切换“演示：全部通过”再次整批验证，核对供应商后完成起草。
5. 可切换超时场景，查看“结果待确认”阻断；追加或修改票据、变更合同时原创建资格失效。
6. 新建会话走虚拟路径，选择机场合同，添加两条明细并填写月份区间，核对合计后进入起草预览。
7. 添加国外 Invoice 示例，核对票号、USD、开票与到票日期；其税额、税号不编造。国外放行规则待确认，不能通过演示税务验证。

## 原型与业务边界

本原型不连接合同、解析、税务、审批或支付服务。合同、票据、供应商及用户身份均为虚构演示数据，非真实权限验证。选择文件时只记录文件名，不读取或上传文件；详情左侧为票据示意，不是原附件预览。解析及整批回滚通过本地状态演示。起草操作不生成持久化业务单据。页面刷新后会话清空。

PRD 尚待确认的事项未作为既定规则：

| 事项 | 原型处理 |
| --- | --- |
| Q01 到期合同 | 展示但禁止选择，并说明待确认 |
| Q02 真实服务月 | 暂用单月控件，页面说明属于演示假设 |
| Q03 非机场虚拟服务月 | 隐藏，待业务确认 |
| Q04 附件限制 | 未硬编码格式、数量、大小的业务限制；本地文件不上传 |
| Q05 金额定义与精度 | 发票金额、含税金额分字段展示，示例暂映射相同；两位小数；零额负额暂不放行 |
| Q06 查重与回滚 | 仅演示业务状态，不能证明真实事务、占用或补偿能力 |
| Q07 国外 Invoice | 可演示解析、编辑；验证保持待确认，不放行 |
| Q08 多币种合单 | 分币种汇总，创建区提示待确认，仅允许看回填预览，不自动换汇或拆单 |
| Q09–10 供应商与起草 | 虚拟路径不强制添加供应商，目标页面为独立预览，不声称已保存草稿 |
| Q11–12 安全与恢复 | 未接入鉴权、审计、持久化会话与性能服务 |

真实应用上线仍需后端权限、接口契约、幂等、精确金额、服务端整批验证与补偿实现。

## GitHub Pages 部署

已配置 `.github/workflows/deploy-pages.yml`：推送 `main` 后自动使用 Node.js 22 安装锁定依赖、构建并部署静态站点。Vite 资源路径使用相对路径，兼容 `/personal/` 子目录。

仓库管理员首次需在 Settings → Pages → Build and deployment → Source 选择 **GitHub Actions**，然后在 Actions 中运行 **Deploy prototype to GitHub Pages**（或再推送到 main）。最终访问网址以成功部署任务返回的 page_url 为准，通常为 `https://chenchong-jx.github.io/personal/`。
